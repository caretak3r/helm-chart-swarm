# certificates fixtures

Test-only TLS material for chart-test-swarm certificate scenarios.
These keys/certs are intentionally short-lived and used ONLY for
local kind cluster testing. They are never used in production.

## Files

- `selfsigned-clusterissuer.yaml` — ClusterIssuer (selfSigned) used by
  self-signed-ca and wildcard scenarios.
- `letsencrypt-staging-clusterissuer.yaml` — ClusterIssuer (ACME) targeting
  the Let's Encrypt staging endpoint. The private key is generated by
  cert-manager at runtime.
- `manual-tls/` — PEM certificate and key files plus Kubernetes Secret
  manifests for manual-tls-secret scenarios:
  - `ca.{crt,key}` — RSA 2048 CA used to sign basic and multisite leaf certs.
  - `basic-cert.{crt,key}` — RSA 2048 leaf with SAN `sample.sample.svc`.
  - `multisite-cert.{crt,key}` — RSA 2048 leaf with 3 SANs.
  - `ecdsa-ca.{crt,key}` — ECDSA P-256 CA used to sign the ECDSA leaf.
  - `ecdsa-cert.{crt,key}` — ECDSA P-256 leaf with SAN `sample.sample.svc`.
  - `manual-tls-{basic,multisite,ecdsa}-secret.yaml` — Kubernetes Secret
    manifests (type: kubernetes.io/tls) built from the above certs.

## Security note

Fixtures in this directory are committed intentionally for reproducibility.
No production CA keys or certificates live here.

The `selfSigned` issuer generates its own key pair at runtime — there are
no static private keys for cert-manager scenarios.

The `manual-tls/` PEM private keys are test-only ephemeral keys generated
for local kind cluster testing. They use a static passphrase of '' (empty)
and are signed by a self-signed test CA. These keys are NEVER used in
production or bound to any production-shaped certificate.
